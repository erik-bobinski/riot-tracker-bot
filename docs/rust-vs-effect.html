Rust → Effect, week one

The first look measured 43 minutes of a boot. This one measures two quiet weeks on the same Railway box, then asks whether the rewrite was worth it.

Week-one verdict

The bill is a wash. The process is fatter. The API is quieter.

Effect still uses 76% less egress, but that is mostly because it stopped downloading 20 League matches a minute. Memory is +41% and sawtoothed. CPU is 4% lower once you stop measuring a cold start. Hobby monthly run-rate: $3.57 Rust vs $3.63 Effect.

Memory

Effect's extra RAM is stable-ish, and it is GC. Not a leak.

Rust climbed slowly from 183 MB to 249 MB over the week, then sat there. No spikes. p99 is 250 MB. It looks like a process that found a pile of memory and kept it.

Effect's quiet week mean is 329 MB. p50 320, p95 417, max 492. That 100 MB gap between typical and p95 is the Node sawtooth. Linear slope is +9.6 MB/day, but the week ended at 331 MB after starting at 310, so the slope is the teeth, not a leak running away. Deploy nights are a different animal: 630 to 716 MB while Railpack is still wiping its hands.

The first-night report said +22% (240 vs 293). A week of GC later, the honest number is +41% on the mean and +67% on p95. The original Effect window started fourteen minutes after Merge effect/rewrite into production. It measured a boot.

Network

The 74% egress drop survived the week. Credit the rewrite's API diet, not Tokio vs libuv.

Hourly Railway NETWORK_TX_GB summed over seven days: Rust 5.25 GB out, Effect 1.25 GB out (−76%). Ingress 272 GB vs 79 GB (−71%). Ratios match the 43-minute first look (egress −74%, ingress −69% on that night). Absolute ingress looks insane until you watch one poll: a single Cloudflare 443 flow dumped 967 KB + 717 KB in two seconds. Do that for eight League accounts pulling full match JSON, every minute, and the week writes itself.

Rust's LoL client requested /match/v5/.../ids with no count, so Riot's default 20, then downloaded all 20 match bodies every poll. Effect asks for 3 and hydrates those 3. Cadence shifted too. Rust used a 60s tokio::interval. Effect uses Schedule.spaced("1 minute"), which waits a minute after the previous poll finishes. Observed gaps: ~70s. About 14% fewer ticks, and ~85% fewer League match bodies. That is the network story. The runtime is along for the ride.

Flow logs for the current deploy, 30 minutes of sample: 98% of bytes are internet TCP/443, the rest is local DNS. No private-service peers. Dropped packets exist (49 in six hours) and they are TCP_INVALID_SYN / TCP_CLOSE noise from the internet, not the bot falling over. DNS in that slice: Riot, Henrik, two lookups for discord.com, all NOERROR.

Work, failures, cost

Useful work is tiny. 429s are not.

Live status via Railway SSH: 8 Discord accounts, 14 game bindings (6 play both, 2 League only), polling not paused, DB at /data/riot-tracker.sqlite. From 4,000 poll-finished lines covering Aug 22 to 25: 7 to 8 accounts scanned, ~11 to 17 match reports per day, never more than one report in a tick. Polls do not fail closed. They skip.

Hobby keeps 7 days of logs, so the entire Rust era is gone. What we have for Effect is loud. One 8-hour slice on Aug 20 produced 500 warnings, every one skipping account this poll, every one HTTP 429 on League match-v5 ?count=3, "server rate limit exceeded," spread evenly across all eight Riot IDs. Typed failures did the job. The poll continued. The accounts got holes. Immediate retries with no backoff (fixed today in production) made it worse. Structured concurrency did not invent a smaller Riot rate limit.

Deploy count is the other operational tell. Rust's final week: 0 deploys. Effect's quiet week: 0 deploys. Effect's most recent week: 7, because Cursor agents can actually ship TypeScript. Zero Effect-era FAILED deploys. Two historical Rust FAILED deploys, both in July, both toolchain/build. Latest Effect Railpack build: 71 seconds, Node 24.19.0, pnpm 11.16.0. A Rust cargo build --release log from Aug 1 still exists; the pin-the-toolchain saga around July 3 is sitting right there in deployment history. Image size is not in Railway's API. The start command still says if [ -f package.json ]; then pnpm start; else /app/bin/riot-tracker-bot; fi, which is the rewrite leaving a ghost in production.

Questions

Is Effect's extra memory stable, growing, or GC-driven?

GC-driven, with a higher floor. Quiet-week p95 sits ~100 MB above p50. Deploy spikes to 700 MB. Not an unbounded leak over seven days.

Does the lower network usage persist under comparable workload?

Yes, −76% egress and −71% ingress on matched quiet weeks, same 7 to 8 accounts. Persistently unfair, because the rewrite also changed how much Riot JSON a poll buys.

Did the rewrite change polling cadence or API call volume?

Both. 60s wall vs ~70s spaced. League 20-match default vs count=3. Henrik v3 default vs v4 size=3. Effect still hydrates every ID it asks for, just fewer of them.

Any measurable operational benefit from structured concurrency and typed failures?

Yes, in the logs we still have. A 429 skips one account for one tick instead of taking down the poll. Aug 20 would have been a worse night in a language that treated that as fatal. It did not prevent the 429s. A backoff landed in production today.

What does Rust still do embarrassingly better?

The working set. 234 MB mean, 252 MB peak, no sawtooth, no 700 MB boot. CPU variance. A native binary that does not care about Node 24 or Corepack. Build cache that is a compiler, not a pnpm store. If this bot tracked 10,000 accounts, this paragraph would be the whole report.

What does Effect make easier enough to justify the runtime tax?

Shipping. Game adapters, JSON logs, an admin CLI that opens the same SQLite file instead of a Unix socket, agents that can typecheck and PR. The last two weeks of Effect history are a feature factory. The last two weeks of Rust were one admin CLI and a long nap. At 8 accounts the bottleneck is Riot's match-v5 limit and your patience, not vCPU.

Strange, cool, or funny production details

The start command still knows how to launch /app/bin/riot-tracker-bot if package.json disappears. One tracked Riot ID is adderall abuser#candy, last reported 21:48 UTC today. Hobby's 7-day log window ate every Rust line, so this report can quote Effect 429s in high definition and Rust errors not at all. Discord snowflakes got rounded once during the JSON->SQLite migration and had to be surgically put back. accountsScanned flickers between 7 and 8 because someone keeps hopping on and off. Ingress is almost all Cloudflare. The original Effect 43 minutes began at the exact second of a docs deploy.

Conclusion

Was the rewrite worth it?

For this bot, yes, with the skepticism the first night skipped. You did not save money. You spent ~95 MB of always-on RAM and a GC sawtooth to get a codebase people actually change, failures that skip instead of crater, and 5x fewer League match bodies per tick. The last of those is an application choice you could have made in Rust. The first two are why you did not.

If the goal was a thinner process, Rust still wins and it is not close. If the goal was a game-agnostic Discord bot that eight friends use and agents can patch on a Tuesday, Effect is doing the job, and the Hobby bill cannot tell the difference.
